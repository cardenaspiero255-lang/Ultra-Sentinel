# Bounded generic JVM behavior probes

`GenericJvmMetamorphicProbe` examines public static methods and Kotlin singleton methods with one or two `Int`/`Long` arguments and an `Int`/`Long` result. It varies one argument over `0`, `1`, and the type maximum, holding another argument at `1` or `100`, and repeats each call. A strictly changing direction becomes a **hypothesis**, with the concrete inputs, observations, method signature and artifact digest. The probe does not take an expected defect, rule, oracle or repair as input.

A turning point can be intended. Exceptions, nulls and inconsistent repeated results cause abstention; unsupported methods, nested classes and unloadable classes are counted. No finding certifies a defect, family novelty, source provenance, a repair or a clean result. The restricted samples do not cover general Kotlin APIs, private methods, arbitrary objects or multi-file causality.

Run untrusted bytecode only through `tests/fixtures/jvm-metamorphic/run-probe.sh`: it uses Bubblewrap without network, a cleared environment, read-only mounts, memory and time limits, and a bounded output. A hostile program shares the probe's JVM and may interfere with its output, so reports are untrusted hypotheses even if their artifact hash matches. Source-to-bytecode provenance and an independent executable product oracle remain separate requirements.

The development replay compiles pinned original `BatteryTelemetry.kt` from GameHub and a pre-existing scoped intervention. Without hardcoding its class or method into the probe, the original produces `0, 100, 0` when its first argument increases; the intervention removes that turning point. An independent Kotlin/JVM oracle verifies the original failure and corrected behavior, rejects a deliberately wrong intervention, and exercises local Git Judge and exact-tree rollback. This example was already known and is not a blind test or a new-family discovery. Any future evaluation must freeze the engine first and use a fresh, independently adjudicated cohort.
