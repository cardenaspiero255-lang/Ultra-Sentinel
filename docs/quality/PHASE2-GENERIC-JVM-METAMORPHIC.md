# Bounded generic JVM behavior probes

`GenericJvmMetamorphicProbe` examines public static methods and Kotlin singleton methods with one to three integral arguments and an integral result. It varies one argument over `0`, `1`, and the type maximum, holding the other arguments at `1` or `100`, and repeats each call. A strictly changing direction becomes a **hypothesis**, with the concrete inputs, observations, method signature and artifact digest. The probe does not take an expected defect, rule, oracle or repair as input.

A turning point can be intended. Exceptions, nulls and inconsistent repeated results cause abstention; unsupported methods, nested classes and unloadable classes are counted. No finding certifies a defect, family novelty, source provenance, a repair or a clean result. The restricted samples do not cover general Kotlin APIs, private methods, arbitrary objects or multi-file causality.

The next candidate also derives input objects from public `Comparable` constructors with one to three integral or string parameters, including nested Kotlin classes. It checks sign antisymmetry and transitivity against the [JDK 21 interface contract](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Comparable.html#compareTo(T)), using fresh instances and repeated observations. It reports constructor signatures, concrete input vectors and observed signs, without target class names, source-specific predicates or expected results supplied by the caller. Unsupported constructors and exceptions remain explicit abstentions. Pair, triple, constructor and finding budgets fail closed. These bounded contract checks do not establish completeness or independence of an external oracle.

Development evidence: a cyclic synthetic order first failed the transitivity regression because pairwise antisymmetry alone missed it; the implementation then detected the cycle while retaining valid numeric and string controls. These are development fixtures, never unknown original Kotlin discoveries. Freeze the complete candidate commit before selecting a new original cohort. Preserve failed evaluations and seal predictions before independently executed truth; do not retune against a revealed cohort.

Run untrusted bytecode only through `tests/fixtures/jvm-metamorphic/run-probe.sh`: it uses Bubblewrap without network, a cleared environment, read-only mounts, memory and time limits, and a bounded output. A hostile program shares the probe's JVM and may interfere with its output, so reports are untrusted hypotheses even if their artifact hash matches. Source-to-bytecode provenance and an independent executable product oracle remain separate requirements.

The development replay compiles pinned original `BatteryTelemetry.kt` from GameHub and a pre-existing scoped intervention. Without hardcoding its class or method into the probe, the original produces `0, 100, 0` when its first argument increases; the intervention removes that turning point. An independent Kotlin/JVM oracle verifies the original failure and corrected behavior, rejects a deliberately wrong intervention, and exercises local Git Judge and exact-tree rollback. This example was already known and is not a blind test or a new-family discovery. Any future evaluation must freeze the engine first and use a fresh, independently adjudicated cohort.
