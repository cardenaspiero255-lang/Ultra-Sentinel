# C2 original-source per-project oracle isolation — trusted self-test v1

**Status:** production-source execution NOT ENABLED; `NOT_CERTIFIED`. Implemented under draft PR #216. This stage tests the transport boundary and independent byte verifier before any of the 169 metadata-only prospective PRs may be released for a real project-specific source oracle.

## Completed architecture in this change

1. **Isolated producer** `.github/workflows/c2-project-oracle-isolation.yml` checks out an exact owner SHA with no retained credential, runs `npm run check`, then installs Bubblewrap and its restricted AppArmor user-namespace profile on a disposable GitHub runner. It executes a *repository-owned* original/fixed/benign fixture through `scripts/c2-project-oracle-isolated-worker.sh`. The original intentionally fails one assertion, while fixed and benign phases pass. No external project source is downloaded or executed.
2. Each run uses Bubblewrap `--unshare-all --new-session --die-with-parent`, a read-only `/workspace`, read-only executable/runtime mounts, private tmpfs, no token/environment, a timeout, and bounded logs. The fixture itself tests absence of credentials and non-loopback network interfaces, prohibition of host path writes and lack of root UID. If namespace or AppArmor fails, **the job fails**.
3. The worker records SHA-1 Git blob hashes of the three actual fixture source bytes, SHA-256 of every source and independent runtime log, deterministic phase order, exit code contract, worker Git SHA and a canonical receipt hash. The original/fix/benign source files and log files remain in a separate artifact; arbitrary JSON assertions cannot create GOLD.
4. **Independent verification job:** separate GitHub Actions job with a fresh checkout downloads the producer's exact named artifact from the same run, authenticates owner, repository, expected HEAD SHA and artifact name/digest against GitHub API, then rehashes every downloaded source/log with `scripts/c2-project-oracle-receipt.cjs`. Its offline module deliberately reports `ownerArtifactAndRunProvenanceAuthenticated=false` since source-only offline verification cannot itself authenticate GitHub; the surrounding trusted job performs API checks. Even a wholly successful two-job chain remains `newGoldLabels=0` and `tripleSPlusCertified=false`.
5. Contract adversarial tests reject changed source bytes, altered logs, symlinks, additional artifact members, reordered/missing phases, mixed SHA and false certification flags.

## Important difference between working infrastructure and real prospective truth

This three-phase smoke test **does not prove that a real upstream Android/Kotlin defect has been reproduced**. The original stage is *deliberately* failing test-only code. The runner currently has **no allowlist of released original candidate source trees or project-specific test recipes**, no validated Android/Gradle build under Bubblewrap, no original upstream JUnit or functional equivalence mapping to an implemented Sentinel rule, and no validated causality or train/test lineage separation. Therefore no actual prospective source worker runs and no new labels can be admitted as GOLD.

For each new external project, a separate **trusted, reviewed source-release/recipe** must bind a pinned original Git tree and original fail->fix->benign oracle: a source-only job verifies license and training exclusion; an isolated project adapter compiles/tests genuine upstream source with build dependencies preprovisioned *inside the sandbox*, exports original JUnit XML and three disjoint evidence manifests; a distinct owner-only receipt attestor reacquires original Git blobs/artifacts from GitHub, independently rehashes ZIP bytes and source hashes, authenticates upstream test results and causal identity, then seals truth before any detector predictions are loaded. Every missing or unsupported project returns `INCONCLUSIVE`, not a label.

**No silent privilege escalation:** repository `pull_request` events exercise only the trusted fixture; no workflow accepts an arbitrary project command, executes an upstream workflow file, copies credentials into a source sandbox, modifies GameHub, creates a GOLD label or merges code. External original-source execution is deliberately gated on future explicit reviewed project adapter implementation and owner-only provenance control.
